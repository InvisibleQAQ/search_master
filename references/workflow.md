# 多源搜索：调研、深搜、跨平台问题

> 用户要"调研 / 深搜 / 找全 / 大家怎么看"，或一个问题要跨多个平台时用这个流程。只查一个事实时不用，直接按 SKILL.md 的路由表调一个工具。

## 目标

搜到"最多的信息"不是目标。结果条数越多，上下文越挤、重复越多、静默失败越难发现。目标是三件事：

1. 覆盖尽量多的**来源层**，每层有独立来源。
2. 关键的几篇读全文（**深读**）。
3. 每条结论至少有 2 个独立来源（转载不算）。

## 来源层

| 层 | 回答什么 | 典型平台（路由见 SKILL.md） |
|---|---|---|
| 公开网页 | 网上公开写过什么 | 中英文网页、新闻、搜索引擎结果页 |
| 社区一手说法 | 真实用户、从业者怎么说 | 知乎、小红书、微博、公众号、X、Reddit、HN、V2EX、脉脉、B站/YouTube 评论 |
| 专业资料 | 原始材料、权威数据 | 论文、GitHub 和代码、库文档、行情、CVE、专利、法律原文 |
| 个人收藏 | 用户以前存过什么 | favbase |

不是每个题都要四层全开，拆题时决定开哪几层。中文专业话题在 X 上本来就少，英文技术话题在小红书上本来就少：按话题选平台，别为了"全"硬搜。

## 深度档位

| 档 | 做法 | 什么时候用 |
|---|---|---|
| 快速 | 主 agent 自己跑 1-2 个工具，搜一轮，不开子 agent | 查一个事实、一个链接 |
| 标准 | 按来源层开 2-4 个子 agent 并行，读前 5-10 篇全文，再核对 | 默认的调研档 |
| 穷尽 | 用 Workflow 编排：分层广搜、两轮滚雪球、专人挑错 | 用户明确要"穷尽"时。Workflow 必须由用户在消息里写"用 workflow"或"ultracode"才能调，不能自己推断 |

用户没说档位时，调研类问题默认标准档，并在回复开头说明用了哪一档。

## 五步

1. **拆题**：拆成 3-5 个子问题。每个子问题按工具的写法准备关键词：
   - anysearch：一条 query 只放一个意图；不写 `site:`；中英文各一份。
   - exa：写成对理想页面的一句描述；需要时在 query 里加 `category:news|company|people|publication|personal site`。
   - X：关键词加引号；可以用 `from:`、`since:`、`min_faves:`、`lang:`。
   - 小红书、微博、B站：用普通人的说法，不用行业术语。
2. **分层广搜**：按上表开层，各层并行。每层按路由表用首选工具，失败再用备选。
3. **深读**：按"被几个独立来源同时提到"排序，取前 5-10 篇，按各平台 reference 的"读全文"命令拿全文。摘要只能当线索，不能当证据。
4. **滚雪球**：从全文里找出新的人名、术语、作者、引用链接，搜第二轮。第一轮你只知道问题叫什么，第二轮才知道圈内人怎么称呼它、关键人物是谁。
5. **核对**：每条结论要有 2 个独立来源；逐条过 SKILL.md 的"静默失败检查"。

## 开子 agent 的写法

- 按来源层分，不按工具分。每个子 agent 的提示里写清：子问题、要开的平台、要读的 reference 文件的完整路径、返回格式。
- 子 agent 只交回整理好的清单，不交原始结果。每条：`结论 | URL | 来源平台 | 日期 | 是否读过全文`。
- bb-browser 是共享资源：bb.sh 自带全局锁，多个子 agent 的 bb 调用会自动排队。所以别把 bb 的活拆给很多个子 agent，拆了也快不了。小红书的活只交给一个子 agent，保证 10 秒间隔。
- neo 每个子 agent 同时最多 5 个 tab，单次 `run` 最长 30 秒。

## 网络

anysearch、exa、context7 走本机代理，经常整段时间 `fetch failed`。每个广搜方案都要有退路：WebSearch / WebFetch（在服务端执行）和 neo（Chrome 走自己的网络）不受影响。判断方法和兜底规则见 `web.md` 最后一节。

## 输出

- 回复开头写：用了哪一档、开了哪几层、每层用了哪些工具、哪些工具失败了。
- 每条结论后面跟来源链接和日期。只有一个来源的结论要标出来。
- 没查到、查不清的写 `[UNKNOWN]`，不要用模糊措辞带过。
- 用户要文件时，写成 Markdown，放用户指定的位置。
