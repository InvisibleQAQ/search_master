# 多源搜索：调研、深搜、跨平台问题

> 用户要"调研 / 深搜 / 找全 / 大家怎么看"，或一个问题要跨多个平台时用这个流程。只查一个事实时不用，按 SKILL.md 派 1 个搜索子 agent 就够。

## 目标

搜到"最多的信息"不是目标。结果条数越多，上下文越挤、重复越多、静默失败越难发现。目标是三件事：

1. 覆盖尽量多的**来源层**，每层有独立来源。
2. 关键的几篇读全文（**深读**）。
3. 每条结论至少有 2 个独立来源（转载不算）。

## 来源层

| 层 | 回答什么 | 典型平台（路由见 SKILL.md） |
|---|---|---|
| 公开网页 | 网上公开写过什么 | 中英文网页、新闻、搜索引擎结果页 |
| 社区一手说法 | 真实用户、从业者怎么说 | 知乎、小红书、微博、公众号、X、Reddit、HN、V2EX、脉脉、B站/YouTube 评论 |
| 专业资料 | 原始材料、权威数据 | 论文、GitHub 和代码、库文档、行情、CVE、专利、法律原文 |
| 个人收藏 | 用户以前存过什么 | favbase |

不是每个题都要四层全开，拆题时决定开哪几层。中文专业话题在 X 上本来就少，英文技术话题在小红书上本来就少：按话题选平台，别为了"全"硬搜。

## 深度档位

| 档 | 做法 | 什么时候用 |
|---|---|---|
| 快速 | 派 1 个子 agent，跑 1-2 个工具，搜一轮 | 查一个事实、一个链接 |
| 标准 | 按来源层并行派 2-4 个子 agent，合计读 5-10 篇全文，主 agent 核对 | 默认的调研档 |
| 穷尽 | 用 Workflow 编排：分层广搜、两轮滚雪球、专人挑错 | 用户明确要"穷尽"时。Workflow 必须由用户在消息里写"用 workflow"或"ultracode"才能调，不能自己推断 |

用户没说档位时，调研类问题默认标准档，并在回复开头说明用了哪一档。

## 五步

分工：拆题、核对由主 agent 做，只有它看得到所有层的清单；广搜、深读由子 agent 做；滚雪球是主 agent 拿各子 agent 交回的新线索，再派一轮。

1. **拆题**：拆成 3-5 个子问题，每个写清要回答什么、用户给的约束和已知线索（术语、人名、链接），填进提示模板。主 agent 不写工具语法：各工具的查询怎么写（anysearch 一条 query 一个意图、exa 写成对理想页面的描述、X 的高级语法等）在 `rules.md` 和平台 reference 里，由子 agent 自己写。
2. **分层广搜**：按上表开层，各层并行。每层按平台 reference 的路由表用首选工具，失败再用备选。
3. **深读**：子 agent 在本层挑有一手经验或独立观点的几篇，同等条件下优先被多个独立来源提到的；转载、README 改写不管出现多少次都只算一个来源，别按出现次数挑（实测：出现最多的恰恰是 README 转载）。挑好后按各平台 reference 的"读全文"命令拿全文；读不到的交给 neo 重读（`read-url.md`）。跨层被多次提到、还没读过全文的，主 agent 再派子 agent 去读。摘要只能当线索，不能当证据。
4. **滚雪球**：主 agent 汇总各子 agent 交回的新线索（人名、术语、作者、引用链接），拆成第二轮的子问题，填进提示模板的"线索"，再派一轮。第一轮你只知道问题叫什么，第二轮才知道圈内人怎么称呼它、关键人物是谁。
5. **核对**：每条结论要有 2 个独立来源。验证码页、登录框这类内容层的静默失败由子 agent 查，写在交回清单的"失败的工具"里；主 agent 只看清单里看得到的：URL 是不是目标平台、日期是否可信、条数是否少得可疑。

## 开子 agent 的写法

- 提示模板和交回格式见 SKILL.md "谁来搜"，照抄模板，不要自己另写。
- 按来源层分，不按工具分。
- bb-browser 是共享资源：bb.sh 自带全局锁，多个子 agent 的 bb 调用会自动排队。所以别把 bb 的活拆给很多个子 agent，拆了也快不了。小红书的活只交给一个子 agent，保证 10 秒间隔。
- neo 每个子 agent 同时最多 5 个 tab，单次 `run` 最长 30 秒。

## 网络

anysearch、exa、context7 走本机代理，经常整段时间 `fetch failed`。每个广搜方案都要有退路：WebSearch 在服务端执行，不受影响；neo 读国内站照常，但代理上游节点断了时境外站也打不开 [实测]；WebFetch 断网时能不能用，证据相反 [UNKNOWN]。判断方法和兜底规则见 `web.md` 最后一节。

## 输出

- 回复开头写：用了哪一档、开了哪几层、每层用了哪些工具、哪些工具失败了（取自子 agent 交回的"失败的工具"）。还在等用户登录或验证、没读到的网址也列出来。
- 每条结论后面跟来源链接和日期。只有一个来源的结论要标出来。
- 没查到、查不清的写 `[UNKNOWN]`，不要用模糊措辞带过。
- 用户要文件时，写成 Markdown，放用户指定的位置。
